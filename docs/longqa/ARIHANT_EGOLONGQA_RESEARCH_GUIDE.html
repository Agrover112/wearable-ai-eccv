Arihant's EgoLongQA
approaches, prompts, settings, and evidence

A code-reading guide to the most consequential EgoLongQA experiments in the original branch. The central story is not a new trained model: it is an inference-time search over which frames to show Qwen3-VL, followed by a small amount of arbitration when two evidence views disagree.

0. Start here the short answer

The best completed local validation run is a pivot/uniform disagreement verifier: a temporal proof-pack answerer is compared with a uniform64 answerer, and Qwen3-VL is called again only for the 122 disagreements. It reaches 539/700 = 77.00%. The best evidence-selection-only variants sit at 528–529/700; the high-resolution uniform baseline reaches 514/700.

2. Task and evaluation 700 video questions

Each EgoLongQA row contains a long egocentric video, one multiple-choice question, four answer options, and the gold field mcq_answer. The model must return one of A, B, C, or D. The canonical validation split has 700 rows; the dev140 and dev20 subsets are iteration tools, not independent leaderboard claims.

FactWhy it changes the experiment
Videos are roughly ten minutes; source capture is about 15 fpsShowing every frame is impossible, so frame selection is the main scientific bottleneck.
Four options, A–DPrompts can be strict one-letter MCQ prompts; likelihood and verifier variants must still map back to option letters.
Gold option C appears in 444/700 rows (63.4%)Raw accuracy can be inflated by always-C or other answer-format shortcuts.
About 79.1% of questions have temporal cuesWords such as before, after, first, and last justify a temporal selector.
Reported metric is raw accuracy, with shortcut-aware diagnosticsUse temporal/non-C/macro breakdowns to decide whether a gain is visual reasoning or label bias.
Local evidence only. The numbers in this guide are completed validation runs recorded in the repository ledger. They are not organizer test-set or public competition leaderboard results.

3. Shared inference path selection → answer

Every winning recipe is an inference-time wrapper around the same answer model. Some recipes use SigLIP2 or a second Qwen call to decide which images to show, but the final answer is generally produced by Qwen3-VL-8B-Instruct with the same concise MCQ prompt and deterministic decoding.

decode videomodel.py::extract_frames()
Read FPS and frame count with OpenCV. Uniformly sample a candidate set, convert BGR to RGB PIL images, and preserve the original frame index and timestamp.
select evidenceuniform, SigLIP2, pivot, or entropy
Choose at most 64 chronological frames. A selector may start with 128 candidates, but Qwen receives the final pack only.
build multimodal requestmodel.py::VLLMModel.generate()
Encode each selected PIL image as a JPEG data URL and insert image content before the question text in one OpenAI-compatible user message.
answer onceQwen3-VL / vLLM
Temperature 0, usually max_new_tokens=16, and strict letter extraction. The selector is not a separately trained head.
record evidencepredictions.jsonl + results
Write the answer, selected indices/timestamps, prompt/settings, cache fingerprints, evaluation result, and diagnostics so a run can be audited without rerunning the model.

The direct answer prompt

Watch the video and answer the following multiple-choice question.

Question: {question}

Options:
{mcq_options}

Important implementation detail. --max-frames is a cap, not the sampling request. The baseline sets both --frames-per-interval 64 and --max-frames 64. Changing only the cap can leave fewer candidate frames than intended.

5. Winner: disagreement verifier 539/700

The winning recipe separates two problems. First, obtain two independently useful views of the video: a temporal-pivot proof pack and a uniform64 pack. Second, let Qwen arbitrate only when those views produce different letters. Agreements do not spend another model call.

primary predictiontemporal pivot
Use the question-conditioned proof pack and store its answer, selected frames, operator, and evidence roles.
secondary predictionuniform64
Run the same final Qwen answer prompt on a broad, evenly spaced 64-frame view.
agreement gatestable sample key
If letters agree, copy the primary answer. If they differ, form one union pack with proof-pack frames plus the missing uniform coverage.
verifier call122 samples only
Ask Qwen to compare all four options, check visible support and temporal order, and return one final letter.

What the audit says

  • Full validation: 539/700, with 122 verifier calls.
  • Relative to the pivot primary: 24 fixes and 13 regressions, a net +11.
  • On disagreements it selected the pivot 76 times, uniform 38 times, and a third answer 8 times.
  • The third answer was correct only once, so unconstrained “think again” behavior is not automatically useful.
  • An oracle that always picked the better of the two candidates would reach 575/700: the remaining gap is arbitration quality, not just frame visibility.

Third-option counterfactual

The eight third-option rows can be audited directly. The temporal-pivot candidate already contained the gold answer on 2/8 rows; the uniform64 candidate contained it on 4/8. The two candidates disagree, so these counts do not overlap. The third answer itself was correct on only one row.

Forced policy on those 8 rowsCorrectRetrospective full-val score
Always fall back to temporal pivot2/8540/700
Always fall back to uniform644/8542/700
Hindsight candidate oracle6/8Not deployable; this is an upper bound for these rows
Answer to the counterfactual. Yes: forcing the verifier to pick one of the two candidates would have been better than allowing a third answer on these rows, especially if it defaulted to uniform64. But it would not guarantee correctness: in two of the eight rows both candidates were wrong. Also, a later candidate-constrained order-swap verifier reached 109/140 on dev140, below the 111/140 pivot, so removing third answers is safer but does not by itself solve arbitration.
Why this won. It made the extra model call conditional on measurable disagreement, and the two packs have complementary failure modes. The verifier is best understood as a cheap candidate arbitration layer, not as a new visual backbone.

6. Coverage-filled temporal pivot 529/700

This is the revised temporal proof pack. It keeps the semantic event selection of the original pivot but changes how the remaining frame slots are filled. Instead of trusting a hand-written “semantic boundary” filler, it greedily covers the largest temporal gap left by the frames already selected.

Answer modelQwen/Qwen3-VL-8B-Instruct through vLLM; temperature 0; max output 16 tokens.
Groundergoogle/siglip2-so400m-patch14-384, bfloat16, batch size 16.
Candidate pool128 uniformly sampled frames.
Temporal slots2 pivot centers, 6 directional target centers, eventlet radius 1, up to 8 bridges.
Global anchors32 uniform anchors.
Fill ruleuniform_coverage: add the candidate farthest from its nearest selected frame, i.e. the largest uncovered gap.
Final packAt most 64 frames, sorted chronologically, shown at 451,584 pixels/frame.

candidates = uniform_sample(video, n=128)

pivot_scores = siglip2_score(candidates, pivot_query(program))
pivots = temporal_nms(top(pivot_scores), count=2, radius_seconds=10)

targets = directional_targets(
    candidates,

    direction=program.direction,
    count=6,
)

selected = eventlets(pivots, radius=1) + eventlets(targets, radius=1)
selected += bridges_between(pivots, targets, max_count=8)
selected += uniform_anchors(candidates, count=32)
selected = fill_largest_uncovered_gaps(selected, candidates, target_count=64)
return chronological(selected)

Full validation was 529/700. The gain over the original pivot was only one answer on 700 rows, and the dev140 run was lower (108/140 versus 111/140), so the fill rule is a useful implementation variant rather than a decisive new scientific result.

7. Exact operator router 529/700

The router asks whether the question actually contains a temporal operation. If the parser returns GLOBAL, it uses the known strong uniform64 policy. Otherwise it uses the temporal-pivot pack. This is a policy-level mixture of two already-tested experts, not a learned gating network.

8. Original temporal-pivot proof pack 528/700

This is the key evidence-selection idea that preceded the winner. A long video is not treated as a bag of equally useful frames. The question is compiled into a small temporal program, SigLIP2 finds a pivot event and target evidence, and the selector adds enough context to make the sequence interpretable.

The original pivot reached 528/700 = 75.43% on full validation and 111/140 = 79.29% on dev140. The dev score is high but should not be treated as a promise about the 700-row result; the full run is the ranking anchor.

Why it was better than generic SigLIP retrieval

Earlier retrieval selected frames with high image/text similarity to the whole question and options. The pivot program adds an explicit ordering constraint: “find the event that makes after or before meaningful, then inspect the required side.” It preserves global anchors so a mistaken pivot does not erase the rest of the video.

9. Uniform64 high-resolution baseline 514/700

Uniform64 is the control that makes the selector results interpretable. It samples 64 positions over the entire video, sends them in chronological order, and uses no SigLIP, temporal parser, or second answer call.

Baseline lesson. Moving from the old 448-pixel budget to 451,584-pixel frames was a substantial improvement over the earlier 64-frame low-resolution control. The top methods therefore compare selection policies at a large visual budget; they are not merely benefiting from more frames.

10. Shannon-entropy probe yes, but not promoted

Yes. Arihant did try a Shannon-entropy-based idea. It was added in the committed run_generate_longqa_uncertainty.py surface and tested late in the experiment sequence. The idea was to use Qwen’s next-token uncertainty as a frame-selection signal: frames that make the answer distribution confident (low entropy) might be more useful evidence.

Bottom line. The temporal-pivot entropy mode reached 16/20 on dev20, versus 17/20 for its uniform reference and 15/20 for the comparable SigLIP pivot. It was promising enough to test, but there is no completed dev140 or full700 entropy run in the ledger, so it does not belong in the top-five ranking.

What entropy was actually computed

The scorer makes a one-token vLLM call with logprobs=True and top_logprobs=100. For each returned token probability p_i = exp(logprob_i), it adds the unobserved probability mass as one aggregate tail bucket. This gives a lower-bound approximation to the full vocabulary Shannon entropy rather than pretending the top-100 distribution sums to one.

m = min(1, Σ pi)    q = max(0, 1 − m)
Hlower = −Σ pi log pi − q log q 
def score_token_uncertainty(frame, prompt):
    top = vllm_one_token(
        frame=frame,
        prompt=prompt,
        temperature=0,
        max_tokens=1,
        top_logprobs=100,
    )
    p = [exp(item.logprob) for item in top]
    observed_mass = min(1.0, sum(p))
    tail_mass = max(0.0, 1.0 - observed_mass)
    entropy = -sum(pi * log(pi) for pi in p if pi > 0)
    if tail_mass > 0:
        entropy -= tail_mass * log(tail_mass)
    return entropy, observed_mass, tail_mass, top

The recorded top-100 tail mass was tiny: mean about 7e-8, maximum about 6.2e-7. Therefore the approximation was close to full-vocabulary entropy; the lack of a clear gain was not caused by a large omitted tail.

Entropy pseudocode

candidates = uniform_sample(video, n=128)

for frame in candidates:
    answer_entropy[frame] = H(
        qwen_one_token(frame, entropy_mcq_prompt(question, options))
    )
    target_score[frame] = -answer_entropy[frame]

pivot_presence[frame] = P("Yes") - P("No")(
    qwen_one_token(frame, presence_prompt(program.pivot))
)

pack = temporal_pivot_selector(
    target_scores=target_score,
    pivot_scores=pivot_presence,
    pivot_centers=2,
    target_centers=8,
    anchors=24,
    bridges=8,
    fill_mode="uniform_coverage",
    final_max_frames=64,
)

answer = qwen3_vl(pack, direct_mcq_prompt(question, options))
Why the idea is plausible but fragile. Low answer entropy means “the model is confident after seeing this frame,” not “this frame is relevant and correct.” A visually misleading frame can be confidently wrong; a genuinely useful frame can leave the model uncertain until it sees surrounding context. The entropy probe was therefore a sensible selector experiment, but not a replacement for broad temporal coverage.

11. Predecessors and dead ends what changed next

The top five make more sense as a progression. These experiments are important because they explain why the branch moved from generic retrieval to temporal programs and finally to arbitration.

ExperimentWhat it triedEvidenceLesson
SigLIP hybrid predecessor 128 candidates; top 16 question/option-retrieved frames plus 64 uniform anchors; final 64 at 448². 498/700 Relevance retrieval helped, but similarity to the whole question does not encode before/after order.
Structured evidence prompt Ask Qwen for evidence/reasoning structure while keeping the same selected frames. 104/140 versus 109/140 for concise pivot on dev140 Prompt verbosity consumed context and did not repair missing evidence.
Timeline summary One Qwen timeline call, then a second answer call. 465/700 Compressing a long video into a generated timeline discarded useful visual detail.
Candidate likelihood / blind likelihood Score option letters from token probabilities, sometimes with a video-blind branch. 107/140 candidate verifier; 90/140 blind-weight dev run Language priors and option-position bias contaminate the score.
QCA / multi-event routing Allocate frame quotas to answer options or parse multiple events. QCA 104/140; QCA router 109/140; multi-event 110/140 Dynamic allocation collapsed to near-uniform quotas; multi-event parsing lacked robust entity linking.
Support/contradiction verifier Ask the verifier to assess support, contradiction, and temporal order internally. 111/140, tied with original pivot A useful prompt refinement, but not a full-val improvement over the unconstrained winner.

Research pattern. The branch repeatedly tested whether a second textual representation or a more elaborate scorer could rescue bad evidence. The strongest result instead came from preserving two concrete visual views and arbitrating their disagreements.

What “same evidence” means here

A frame pack is a set of original video indices. The final images may be resized by the Qwen image processor, but the selector records the pre-resize index and timestamp. This is why proof-pack JSONL is more useful than looking only at the final letter: it lets you ask whether a mistake came from missing the event, misunderstanding its order, or choosing the wrong answer among visible candidates.

Cache identity matters. Grounding and entropy caches fingerprint the selector model/revision, video size and modification time, scoring resolution, prompt/descriptors, and relevant settings. Reusing a cache is safe only when the fingerprint matches.
